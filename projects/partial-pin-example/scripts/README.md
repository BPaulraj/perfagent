# partial-pin-example: k6 performance test scripts

Generated by perfagent (2026-10-24T12:35:23+05:30). **Self-contained:** these scripts run with only the [k6](https://grafana.com/docs/k6/latest/set-up/install-k6/) binary. You don't need Python, the perfagent framework, an AI assistant or internet access. You can copy this folder anywhere (another machine, a CI agent, a load-generator VM).

## Run
```bash
k6 run main.js \
  -e TEST_TYPE=smoke \
  -e BASE_URL=http://localhost:5180 \
  -e WEB_URL=http://localhost:5180
```
PowerShell: put the whole command on one line, or use a backtick (`` ` ``) for line continuation.

| Variable | Meaning |
|---|---|
| `TEST_TYPE` | `smoke` · `load` · `stress` · `spike` · `soak` · `breakpoint` · `quick` (load shapes in `workload.json` → `profiles`) |
| `BASE_URL` | API base URL the scripts call |
| `WEB_URL` | Front-end URL for browser scenarios |
| `SCALE` | Optional load multiplier, e.g. `0.5` (default `1`) |
| `SUMMARY_PATH` | Where to write the full JSON results (default `summary.json` in the current folder) |

Optional extras:
- `K6_WEB_DASHBOARD=true K6_WEB_DASHBOARD_EXPORT=dashboard.html`: live dashboard at http://localhost:5665 and an HTML export. Close the tab when the test ends.
- `--out influxdb=http://localhost:8086/k6`: stream metrics to Grafana.
- `K6_BROWSER_HEADLESS=false`: watch the browser scenarios.

## Results
- The console prints a PASS/FAIL table per scenario against the SLAs.
- **Exit code 0** means all SLAs were met. **99** means a threshold (SLA) was breached. Other non-zero codes are errors. CI pipelines can gate on this.
- `summary.json` holds the complete metrics. The perfagent framework turns it into an HTML report (`python -m perfagent report`), but that's optional.
